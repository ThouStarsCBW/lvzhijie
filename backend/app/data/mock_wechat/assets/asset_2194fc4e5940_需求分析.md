明白了，关键边界要改成这样：

```text
OpenClaw 只负责微信通道
本系统负责法律业务功能
```

下面是重写后的 **需求分析 v0.4**。

**一、项目定位**
本项目是一个面向单人使用的 **个人法律智能工作台**。

系统包含四大核心能力：

1. 基于 OpenClaw 微信插件的微信聊天接入。
2. 法律文件仿 Git 版本控制。
3. 法律案件管理与推理分析。
4. 仿律师事务所结构的法律智能体协同。

其中，**只有微信相关能力依赖 OpenClaw**。  
OpenClaw 在本项目中不是整体智能体底座，而是微信代理层。

**二、OpenClaw 边界**
OpenClaw 只承担这些职责：

- 运行微信插件。
- 接收微信消息。
- 保存或暴露微信聊天记录。
- 执行微信自动回复。
- 作为电脑端向微信发送消息的跳板。
- 维护微信连接状态。

OpenClaw 不承担：

- 案件管理。
- 法律文件版本控制。
- 合同 diff。
- 法律推理。
- AOE 图生成。
- 案件任务管理。
- 法律智能体团队调度。
- 系统数据库主存储。
- 电脑端业务界面。

也就是说，本系统不是“OpenClaw 上的完整业务系统”，而是：

```text
本系统
  -> 读取 OpenClaw 微信聊天记录
  -> 通过 OpenClaw 给微信发消息
```

OpenClaw 只是微信能力的适配层。

**三、整体架构**
```text
微信用户
  -> OpenClaw 微信插件
  -> OpenClaw 保存聊天 / 自动回复
  -> 本系统同步或读取聊天记录
  -> 本系统电脑端展示会话
  -> 本系统案件 / 文件 / 推理 / 智能体模块独立运行
  -> 电脑端发送消息
  -> 本系统调用 OpenClaw
  -> OpenClaw 转发到微信
```

本系统内部业务能力独立，不占用 OpenClaw 的智能体边界。

**四、直接删除的旧功能**
目标用户是单个人，因此删除：

- Clerk 登录。
- 多组织。
- 组织邀请。
- 成员管理。
- 成员权限。
- Board Access。
- 多租户。
- Skills Marketplace。
- Skill Packs。
- Custom Fields。
- Board Groups。
- 复杂审批系统。

保留的认证/连接只包括：

```text
电脑端：本地管理 token 或无登录
OpenClaw：本地连接配置
微信用户：由 OpenClaw 微信插件识别
```

**五、微信模块需求**
微信模块是 OpenClaw 适配层。

功能包括：

- 配置本机 OpenClaw 地址。
- 测试 OpenClaw 连接。
- 读取 OpenClaw 微信会话列表。
- 读取某个微信联系人的聊天记录。
- 同步聊天记录到本系统数据库。
- 标记消息来源：
  - 微信用户
  - OpenClaw 自动回复
  - 电脑端人工发送
  - 系统记录
- 电脑端通过 OpenClaw 向微信发送消息。
- 查看 OpenClaw 微信插件在线状态。
- 查看最近同步时间。
- 查看发送失败原因。
- 支持手动重新同步。

微信消息状态：

```text
synced 已同步
openclaw_auto_replied OpenClaw 已自动回复
draft 本系统草稿
sent_via_openclaw 已通过 OpenClaw 发送
failed 发送失败
ignored 忽略
```

**六、微信自动回复边界**
微信自动回复由 OpenClaw 完成。

本系统不负责直接生成微信自动回复，但可以：

- 展示 OpenClaw 自动回复内容。
- 将自动回复同步进案件聊天记录。
- 标记某条回复由 OpenClaw 自动生成。
- 允许电脑端人工补发消息。
- 允许把本系统生成的法律追问，通过 OpenClaw 发到微信。

如果未来需要本系统参与自动回复，也应作为“草稿建议”，不替代 OpenClaw 微信插件的运行机制。

**七、电脑端聊天工作台**
电脑端聊天工作台用于读取和操作 OpenClaw 微信聊天。

功能：

- 会话列表。
- 聊天记录详情。
- 同步 OpenClaw 聊天记录。
- 手动刷新。
- 搜索联系人或消息内容。
- 一键创建案件。
- 绑定已有案件。
- 电脑端输入消息。
- 通过 OpenClaw 发送到微信。
- 查看发送状态。
- 查看 OpenClaw 自动回复记录。
- 将聊天内容导入案件事实。
- 将聊天内容交给法律推理模块分析。

不做：

- 多客服坐席。
- 客服分配。
- 多人在线。
- 微信插件内部管理。

**八、案件管理需求**
案件模块独立于 OpenClaw。

案件字段：

```text
id
title
case_type
status
summary
wechat_contact_ref
conversation_ref
created_at
updated_at
```

案件类型：

```text
contract 合同纠纷
labor 劳动争议
marriage 婚姻家事
debt 债权债务
traffic 交通事故
company 公司商事
real_estate 房产纠纷
criminal 刑事咨询
other 其他
```

案件状态：

```text
new 新咨询
collecting_info 补充信息中
analyzing 分析中
waiting_user 等用户补充
waiting_owner_review 等主人复核
replied 已回复
closed 已关闭
```

案件页面包括：

- 关联微信聊天记录。
- 案件摘要。
- 事实清单。
- 时间线。
- 证据清单。
- 文件列表。
- 文件版本记录。
- 法律推理结果。
- AOE 推理图。
- 待追问问题。
- 案件任务。
- 操作日志。

**九、仿律师事务所智能体架构**
法律智能体模块独立运行，不依赖 OpenClaw。

智能体应仿真律师事务所结构：

- 主任律师 Agent：总控、分配任务、把关结论。
- 客户接待 Agent：整理咨询问题，但不直接控制微信插件。
- 案件秘书 Agent：提取事实、时间线、证据、诉求。
- 承办律师 Agent：分析法律关系、争议焦点。
- 合同审查律师 Agent：审查合同和版本差异。
- 诉讼策略律师 Agent：分析诉讼路径、举证责任、风险。
- 法律检索 Agent：生成检索方向，后续可接法条案例库。
- 风险质控 Agent：检查过度推断和不确定点。
- 文书起草 Agent：起草回复、意见摘要、文书草稿。

这些智能体服务于案件、文件、推理，不作为 OpenClaw 的一部分。

**十、法律文件版本控制**
法律文件模块独立。

功能：

- 上传法律文件。
- 一个文件支持多个版本。
- 查看版本历史。
- 比较任意两个版本。
- 逐字 diff。
- 段落 diff。
- 高亮新增、删除、修改。
- 绑定案件。
- 记录版本说明。
- 记录版本来源。
- 合同审查 Agent 分析差异风险。
- 输出修改摘要和风险提示。

第一阶段支持：

```text
.txt
.md
.docx 转纯文本
```

重点识别：

- 主体变化。
- 金额变化。
- 付款期限变化。
- 违约责任变化。
- 解除条件变化。
- 管辖条款变化。
- 争议解决方式变化。
- 保密条款变化。
- 责任限制变化。

**十一、法律推理与 AOE 图**
法律推理模块独立。

输入：

- 微信聊天记录。
- 案件事实。
- 案件记忆。
- 文件内容。
- 文件 diff。
- 人工补充信息。

输出：

- 案件事实。
- 当事人关系。
- 时间线。
- 证据清单。
- 用户诉求。
- 争议焦点。
- 法律关系。
- 法律要件。
- 事实与要件匹配情况。
- 初步结论。
- 风险提示。
- 不确定点。
- 待追问问题。

AOE 图节点：

```text
Fact 事实
Evidence 证据
Timeline 时间节点
Issue 争议焦点
Rule 法律规则/要件
Analysis 分析
Conclusion 结论
Uncertainty 不确定点
Question 追问问题
```

边类型：

```text
supports 支持
contradicts 矛盾
requires 需要
leads_to 推导
depends_on 依赖
uncertain_about 不确定
asks 追问
```

追问问题可以由本系统生成，再通过 OpenClaw 发给微信用户。

**十二、OpenClaw 与本系统交互接口**
本系统需要一个 OpenClaw Adapter 层。

职责：

- 连接 OpenClaw。
- 获取微信会话列表。
- 获取聊天记录。
- 发送微信消息。
- 获取发送结果。
- 获取 OpenClaw 状态。
- 将 OpenClaw 消息转换成本系统统一消息格式。

建议内部接口：

```text
OpenClawAdapter.listConversations()
OpenClawAdapter.getConversationMessages(conversationId)
OpenClawAdapter.sendWechatMessage(conversationId, content)
OpenClawAdapter.getStatus()
OpenClawAdapter.syncMessages()
```

业务层只调用 Adapter，不直接耦合 OpenClaw 插件细节。

organizations

**十五、MVP 范围**
第一阶段做：

- OpenClaw 本地连接配置。
- 读取 OpenClaw 微信聊天记录。
- 电脑端通过 OpenClaw 给微信发消息。
- 会话列表。
- 聊天详情。
- 一键建案。
- 案件详情。
- 案件事实整理。
- 法律智能体角色。
- 法律文件上传。
- 文件版本历史。
- 文本/docx diff。
- 合同差异风险分析。
- 法律推理结构化结果。
- AOE 推理图。
- 待追问问题。
- 一键将追问通过 OpenClaw 发微信。

明确不做：

- 让 OpenClaw 承担案件分析。
- 让 OpenClaw 承担文件 diff。
- 让 OpenClaw 承担法律推理。
- 多用户。
- 多组织。
- 权限系统。
- 技能市场。
- 自定义字段。

**十六、最终边界定义**
最终系统边界是：

```text
OpenClaw = 微信插件运行环境 + 微信消息跳板
本系统 = 法律业务系统 + 案件工作台 + 文件版本控制 + 法律推理 + 电脑端界面
```

这版比 v0.3 更准确：  
**OpenClaw 不再是整个法律智能体系统的底座，只是微信接入层。**  
其他法律业务能力都独立出来，避免被 OpenClaw 架构绑住。
